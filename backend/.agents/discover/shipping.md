## Bounded Context: Shipping

- **Purpose**: Quotes delivery costs for orders at checkout and manages the physical delivery lifecycle — labels, carrier handoff, tracking, proof of delivery, and returns receipt — so sellers can fulfill orders reliably.
- **Classification**: Supporting

### Entities

- **Shipment** — aggregate root. `id` (ShipmentId), `orderId`, `destinationAddress` (Address snapshot), `items []ShipmentItem {variantId, qty}`, `weight` (Weight), `methodId`, `carrierName`, `trackingNumber?`, `labelUri?`, `status` (ShipmentStatus), `createdAt/dispatchedAt/deliveredAt`
- **ShippingMethod** — a purchasable delivery option. `id` (MethodId), `name`, `enabled`, `pricing` (RateRule)
- **ShippingZone** — geographic grouping. `id` (ZoneId), `name`, `criteria []ZoneCriterion {country?, province?, postalPrefix?}`
- **Carrier** — a configured delivery provider. `id` (CarrierId), `name`, `kind` (Manual | Integrated), `credentials?`
- **Return** (RMA) — `id` (ReturnId), `shipmentId`, `reason`, `status` (Requested | Authorized | Received | Rejected)

### Value Types

- `ShipmentId`, `MethodId`, `ZoneId`, `CarrierId`, `ReturnId` — string (opaque, DB-generated)
- `Address` — `{name, line1, line2?, city, province, postalCode, country, phone}` — immutable snapshot on Shipment
- `Weight` — int grams
- `Money` — int64 minor units (single currency; matches Product BC)
- `ShipmentStatus` — enum: `Pending | LabelGenerated | Dispatched | InTransit | Delivered | Failed | Returned`
- `RateRule` — `{base Money, perKg Money?, freeOver Money?}` applied against matched zone
- `ShippingQuote` — `{methodId, name, price Money, etaDays?}` — read-only projection returned to Order

### Application Services

- **RateSvc**
  - `QuoteRates(ctx, quoteRequest{destinationAddress, items[]})` → `([]ShippingQuote, error)` — matches zones, applies rules
  - Errors: `ErrNoZoneMatched`, `ErrNoMethodsEnabled`
- **ShipmentSvc**
  - `CreateShipment(ctx, orderData)` → `(*Shipment, error)` — snapshots address/items; requires fulfilled order
  - `GenerateLabel(ctx, shipmentId)` → `(labelUri, error)`
  - `MarkDispatched(ctx, shipmentId)` → `error`
  - `ApplyTrackingUpdate(ctx, trackingNumber, statusUpdate)` → `error` — from carrier gateway/webhook
  - `CancelShipment(ctx, shipmentId)` → `error` — only while Pending/LabelGenerated
  - Errors: `ErrShipmentNotFound`, `ErrInvalidTransition`, `ErrOrderNotFulfilled`
- **ConfigSvc** (admin)
  - CRUD for `ShippingMethod`, `ShippingZone`, `Carrier`
  - Errors: `ErrMethodNotFound`, `ErrZoneNotFound`, `ErrCarrierNotFound`, `ErrZoneInUse`
- **ReturnSvc**
  - `RequestReturn(ctx, shipmentId, reason)`, `AuthorizeReturn`, `RejectReturn`, `ReceiveReturn`
  - Errors: `ErrReturnNotFound`, `ErrReturnAlreadyOpen`, `ErrShipmentNotDelivered`
- **ShipmentQuerySvc** (reads)
  - `GetShipment(ctx, shipmentId)`, `GetShipmentsByOrder(ctx, orderId)`, `Track(ctx, trackingNumber)`

### Domain Services

- **RateCalculator** — matches destination to most specific zone; computes price from RateRule (base + weight + free-over threshold).
- **TrackingRefresher** — normalizes carrier status webhooks/polls into internal ShipmentStatus transitions.

### Ports (storage- and carrier-agnostic)

| Port | Methods |
|---|---|
| `ShipmentRepo` | `Save`, `FindById`, `FindByOrderId`, `FindByTrackingNumber`, `Update` |
| `MethodRepo` / `ZoneRepo` / `CarrierRepo` | `Save`, `FindById`, `List`, `Delete` |
| `ReturnRepo` | `Save`, `FindById`, `FindByShipmentId`, `Update` |

### Ubiquitous Language

| Term | Definition in THIS context |
|---|---|
| Shipment | The physical parcel movement record for one fulfilled order |
| Label | The printable carrier document (or uploaded PDF) for a shipment |
| Tracking Number | Carrier identifier used to follow parcel progress |
| Carrier | The company/person physically delivering parcels |
| Shipping Method | A named delivery option shoppers pick at checkout |
| Zone | A geographic area a method applies to |
| Quote | A computed price+ETA offered for a destination before purchase |
| Dispatched | Parcel handed over to the carrier |
| RMA / Return | Authorized reverse logistics for a delivered shipment |
| Destination Snapshot | Immutable copy of the delivery address captured at shipment creation |

**Polysemes**

- `Address` — Customer BC: editable saved address-book entry. Shipping: immutable snapshot frozen onto a shipment.
- `Method` / `Rate` — Shipping: delivery option and its price rule. Payment: a payment instrument/charge. Same word, unrelated models.
- `Item` — Product: purchasable variant. Shipping: a line entry recording quantity + weight moved in a parcel.

### Capabilities

- Quote delivery prices for a destination at checkout (served to Order)
- Create shipments from fulfilled orders with address/item snapshots
- Generate/store labels; support manual carriers first [Assumed]
- Track delivery status via manual updates or carrier webhooks
- Manage zones, methods, and carriers (admin)
- Authorize and receive returns; hand off refunds to Payment

### Inbound

- Commands handled: `QuoteRates`, `CreateShipment`, `GenerateLabel`, `MarkDispatched`, `ApplyTrackingUpdate`, `CancelShipment`, method/zone/carrier CRUD, `RequestReturn`, `AuthorizeReturn`, `RejectReturn`, `ReceiveReturn`
- Events consumed: `OrderFulfilled` (from Order) → triggers shipment creation [Assumed trigger; could be manual admin action — see open questions]

### Outbound

- Events published: `ShipmentDispatched {shipmentId, orderId, trackingNumber}`, `ShipmentDelivered {shipmentId, orderId}`, `DeliveryFailed {shipmentId, orderId, reason}`, `ReturnReceived {returnId, orderId}` — consumers: Reporting, Order
- APIs exposed: `GET shippingMethods(destination)` (GraphQL, storefront), admin REST `/api/v1/shipping/{methods,zones,carriers,shipments,returns}`

### Dependencies

- **Upstream (serves)**: Order BC — provides rate quotes at checkout and receives fulfillment/tracking events. Pattern: **OHS/PL** for quoting (stable quote shape), **Customer–Supplier** for fulfillment data flow (existing map direction: Order →U Shipping).
- **Downstream (consumes)**: Auth BC — identity for admin/seller operations. Pattern: **OHS/PL**.
- **External**: Carriers — behind `CarrierGateway` ACL. Pattern: **ACL**.

### Data Owned

- `shipments` (+ embedded address/item snapshots)
- `shipping_methods`, `shipping_zones`, `carriers`
- `returns`

### Validation (Step 7)

- Scenario 1 — Checkout: Order → Shipping `QuoteRates`; Shipping reads nothing from Order; coarse-grained, one call. ✅
- Scenario 2 — Fulfillment: Order publishes `OrderFulfilled` → Shipping snapshots its own copies of address/items (no shared tables) → emits `ShipmentDispatched/Delivered`. ✅
- Scenario 3 — Returns: Shipping owns RMA state; refund stays in Payment via Order orchestration — no cross-context writes. ✅
- Single team ownable; language internally consistent; changes to zone rules don't ripple outward. ✅
