## Step 1 — High-Level Domain Map

### Actors
- **Store Admin / Merchant** — discovers, installs, configures, enables, disables, and uninstalls plugins/extensions; configures extension settings and API keys.
- **Extension / Plugin Author (Developer/Vendor)** — builds plugins or integrations that hook into OctaCart extension points (webhooks, lifecycle hooks, UI slots, custom payment/shipping providers).
- **Core Platform Runtime (OctaCart Monolith)** — executes or dispatches extension hooks at predefined interception points in business flows.
- **External Integration Services / Webhook Endpoints** — third-party systems receiving event webhooks or hosting out-of-process extension handlers.

### Business Flows Touching Extension

1. **Extension Lifecycle Management**: Admin installs an extension manifest -> activates/enables extension -> verifies health -> deactivates or uninstalls. [Inferred — standard extension lifecycle]
2. **Extension Configuration**: Admin configures key-value options, secrets, credentials, or toggle flags required by a specific installed extension. [Inferred]
3. **Webhook Subscriptions & Dispatch**: Third-party extensions register webhook subscriptions for specific platform domain events (e.g. `order.created`, `product.updated`) -> system signs and delivers HTTP requests with retry/backoff. [Inferred — clean decoupled extension model for Go monoliths]
4. **Extension Point / Hook Execution**: Core workflows (e.g., checkout validation, custom shipping rate lookup, discount calculation) query registered extension handlers or interceptors. [Assumed]
5. **Sandboxed/Out-of-Process Execution**: External plugins run isolated (via HTTP webhooks, WASM runtime, or gRPC) without compromising monolith stability or memory safety. [Assumed]

### External Systems
- **Remote Webhook Endpoints / Apps** — third-party SaaS systems (e.g. Klaviyo, Mailchimp, QuickBooks, custom ERP) that consume webhooks or provide remote endpoints.
- **Extension Registry / Directory (Future)** — catalog of available installable extensions.

## Step 2 — Domain Events and Commands

### Timeline A — Extension Lifecycle
- `InstallExtension(manifest)` (cmd, Admin) -> `ExtensionInstalled {extensionId, name, version}`
- `EnableExtension(extensionId)` (cmd, Admin) -> `ExtensionEnabled {extensionId}`
- `DisableExtension(extensionId)` (cmd, Admin) -> `ExtensionDisabled {extensionId}`
- `ConfigureExtension(extensionId, config)` (cmd, Admin) -> `ExtensionConfigured {extensionId}`
- `UninstallExtension(extensionId)` (cmd, Admin) -> `ExtensionUninstalled {extensionId}`

### Timeline B — Webhook Registration & Dispatch
- `RegisterWebhook(extensionId, eventTypes[], targetUrl, secret)` (cmd, Admin/Extension) -> `WebhookRegistered {webhookId, extensionId}`
- `DomainEventPublished(event)` (event, from any BC) -> `DispatchWebhook(webhookId, payload)` -> `WebhookDelivered` OR `WebhookDeliveryFailed`
- `RetryWebhook(deliveryId)` (cmd, scheduler) -> `WebhookRetried`

### Timeline C — Hook Invocation
- `InvokeHook(hookPoint, contextPayload)` (cmd/query, core BC) -> returns extension-contributed results or validation signals.

## Step 3 — Boundary Analysis & Clustering

### Problem Signals & Boundary Justification
- **Rate of Change & Stability**: Third-party extension manifests, webhook subscriptions, retry states, and developer endpoints change independently of core catalog or order transactions.
- **Fault Isolation**: Faulty third-party extension endpoints or failing webhooks must not crash or delay core shopping and checkout processes.
- **Security Perimeter**: Secrets, webhook signing keys, scopes/permissions, and authorization to invoke internal APIs are dedicated extension-governance concerns.
- **Single Word Context Name**: **`Extension`** (captures plugins, extensions, add-ons, and integration hooks).

## Step 6 — Map Relationships

- **All Functional BCs** -> **Extension**: Pattern: **Customer-Supplier** (BCs emit events for webhooks; invoke registered extension hooks).
- **Auth BC** -> **Extension**: Pattern: **OHS / PL** (Validates admin permissions to manage extensions; verifies API access tokens issued to extensions).
- **Settings BC** -> **Extension**: Pattern: **OHS / PL** (Provides store base URL and store metadata for webhook signatures).
- **External Webhooks / Systems** -> **Extension**: Pattern: **ACL** (Isolates network timeouts, HMAC signatures, HTTP retries from internal code).

## Step 7 — Validation of Boundaries

- [x] **Single Team / Component Ownership**: Developer/integrations team can maintain the extension engine without touching checkout or product logic.
- [x] **Data Ownership**: Exclusively owns `extensions`, `extension_configs`, `webhook_subscriptions`, and `webhook_deliveries`.
- [x] **Language Consistency**: Words like `Manifest`, `HookPoint`, `WebhookSubscription`, `DeliveryAttempt` belong strictly to this context.
- [x] **Coarse-Grained Integration**: Core BCs publish domain events; Extension BC handles payload signing and HTTP transmission asynchronously.
- [x] **Autonomous Evolution**: Migrating from HTTP webhooks to WASM (WebAssembly) or gRPC plugins can happen entirely inside the Extension BC.

## Step 8 — Document the Result

### Bounded Context Canvas

## Bounded Context: Extension

- **Purpose**: Manages the registration, configuration, lifecycle, security scopes, and hook/webhook execution of third-party plugins and extensions to allow custom functionality without modifying core platform code.
- **Classification**: Generic

### Entities

- **Extension** — Aggregate root representing an installed plugin/extension.
  - `id` (ExtensionId)
  - `shopId` (ShopId) — _Extensions are installed per-store._
  - `identifier` (string, unique slug e.g. `com.vendor.klaviyo`)
  - `name` (string)
  - `version` (string)
  - `status` (ExtensionStatus: `Installed | Enabled | Disabled | Faulted`)
  - `manifest` (ExtensionManifest)
  - `scopes` ([]string)
  - `installedAt`, `updatedAt`
- **ExtensionConfig** — Per-extension merchant settings and secrets.
  - `extensionId` (ExtensionId)
  - `settings` (map[string]string)
  - `secretHash` (string, for signature verification)
- **WebhookSubscription** — Registered outbound event listeners.
  - `id` (WebhookId)
  - `extensionId` (ExtensionId)
  - `shopId` (ShopId)
  - `eventTypes` ([]string)
  - `targetUrl` (string)
  - `secret` (string)
  - `status` (WebhookStatus: `Active | Paused | Disabled`)
- **WebhookDelivery** — Log of webhook dispatch attempts.
  - `id` (DeliveryId)
  - `webhookId` (WebhookId)
  - `eventType` (string)
  - `payload` (string)
  - `statusCode` (int)
  - `durationMs` (int64)
  - `error` (string?)
  - `attemptNumber` (int)
  - `createdAt`

### Value Types

- **ExtensionId**, **WebhookId**, **DeliveryId** — `string` (opaque unique identifier)
- **ShopId** — string (opaque; received from Auth JWT claim for admin ops; not owned by Extension BC)
- **ExtensionStatus** — enum: `Installed | Enabled | Disabled | Faulted`
- **WebhookStatus** — enum: `Active | Paused | Disabled`
- **HookPoint** — enum / string (e.g. `OrderValidate`, `RateCalculation`, `PostPayment`)
- **ExtensionManifest** — `{author, website, description, supportedHooks, requiredScopes}`

### Application Services

- **ExtensionLifecycleSvc**
  - `Install(ctx, shopId ShopId, manifest)` -> `(Extension, error)`
  - `Enable(ctx, extensionId)` -> `error`
  - `Disable(ctx, extensionId)` -> `error`
  - `Uninstall(ctx, extensionId)` -> `error`
  - `Configure(ctx, extensionId, configMap)` -> `error`
- **WebhookSvc**
  - `RegisterWebhook(ctx, shopId ShopId, cmd)` -> `(WebhookSubscription, error)`
  - `DispatchEvent(ctx, shopId ShopId, eventType, eventPayload)` -> `error`
  - `RetryDelivery(ctx, deliveryId)` -> `error`
  - `ListDeliveries(ctx, webhookId, pagination)` -> `(DeliveryPage, error)`

### Domain Services

- **WebhookSigner** — Computes HMAC-SHA256 signatures for outgoing webhook payloads so receivers can verify authenticity.
- **HookDispatcher** — Executes synchronous or asynchronous extension hook handlers with timeout controls.

### Adapters

| Side | Adapter | Purpose |
|---|---|---|
| Driven | `ExtensionRepo` | Persists extensions, configs, and subscriptions |
| Driven | `WebhookDeliveryRepo` | Persists webhook dispatch attempt logs |
| Driven | `WebhookHttpClient` (ACL) | Dispatches HTTP POST requests with HMAC headers, timeouts, and TLS validation |
| Driving | `DomainEventSubscriber` | Receives all core domain events and queues webhook dispatches |
| Driving | `WebhookWorker` | Asynchronous worker processing delivery queues and retry backoffs |
| Driving | `ExtensionAdminRestHandler` | Admin endpoints under `/api/v1/admin/extensions` and `/api/v1/admin/webhooks` |

### Ubiquitous Language

| Term | Definition |
|---|---|
| Extension | An installable, pluggable unit extending core platform capabilities |
| Manifest | Declarative specification of extension capabilities, hooks, and versioning |
| HookPoint | An internal insertion point where extensions can contribute data or intercept flows |
| Webhook | HTTP POST notification sent to an external service when an event occurs |
| HMAC Signature | Cryptographic hash header included in webhooks to guarantee payload authenticity |

### Capabilities

- Install, activate, configure, deactivate, and uninstall plugins/extensions
- Securely store extension credentials, secrets, and merchant configuration keys
- Register webhook endpoints subscribed to platform domain events
- Deliver signed webhook requests with retry policies and exponential backoff
- Provide execution audit logs and failure diagnostics for developers and merchants
- Expose hook points for extensible computation

### Inbound

- Commands handled:
  - `InstallExtension`, `EnableExtension`, `DisableExtension`, `UninstallExtension`, `ConfigureExtension`
  - `RegisterWebhook`, `UpdateWebhook`, `DeleteWebhook`
  - `DispatchEvent(eventType, payload)`
- Events consumed:
  - Subscribes to published events from all core BCs (e.g. `OrderPlaced`, `ProductPublished`, `PaymentCaptured`, etc.) to trigger webhooks.

### Outbound

- Events published:
  - `ExtensionEnabled {extensionId}`
  - `ExtensionDisabled {extensionId}`
  - `WebhookDeliveryFailed {webhookId, deliveryId, reason}`
- APIs / queries exposed:
  - REST (admin): `/api/v1/admin/extensions`, `/api/v1/admin/webhooks`

### Dependencies

  - Auth BC (identity & role gating for admin APIs). Pattern: **OHS / PL**.
  - Settings BC (store URL & basic details for webhook headers). Pattern: **OHS / PL**.
- **Downstream**:
  - External Third-Party Webhook Endpoints / Servers. Pattern: **ACL**.
