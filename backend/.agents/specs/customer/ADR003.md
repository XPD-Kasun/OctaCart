# Reject Deletion of Addresses Linked to Active Orders and Soft Delete Addresses Linked to Past Orders

## The Problem
We need to define the address deletion lifecycle to preserve order history integrity without blocking deletion of unused addresses.

## Options Considered
- **Fail address deletion with `ErrCannotDeleteOnlyAddress` if linked to active/open orders; soft delete if linked only to past orders; permanently hard delete otherwise.**
- Disallow deleting any address that has ever been used in any order.
- Hard delete all addresses and cascade/nullify historical order references.

## Rationale
Active and open orders depend directly on the valid address reference. Past completed orders require historical record preservation (handled via soft delete), while completely unreferenced addresses can safely be purged permanently.

## Notes
Attempting to delete addresses assigned to active/open orders must return `ErrCannotDeleteOnlyAddress`.
