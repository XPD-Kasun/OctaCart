# Domain Entity Go Implementation Style
Encapsulate Domain Entities with Unexported Fields and Return Copies by Value to Driving Adapters

# The Problem
How to prevent domain entities from being mutated by outer layers without adding excessive DTO boilerplate.

# Options Considered
- Full DTO mapping layer for every entity and read model
- Exporting public fields directly on domain entities
- **Unexported struct fields with public getters on entities, returning entities by value (as a copy) to driving adapters**

# Rationale
Returning domain entities by value ensures driving adapters receive an immutable copy, preventing unintended side effects while leveraging Go encapsulation and eliminating tedious DTO boilerplate.

For example,

```go
type Product struct {
    id int
    name string
    price float64
    ...
}

func (p *Product) Name() string { return p.id }
func (p *Product) Price() float64 { return p.price }
```

In above all fields are in lowercase thus private. We are allowing field access through getters. So for JSON serialization, and consumption they can use these getters.

# Notes
Entities expose public getter methods for driving adapters to read values for API serialization.
