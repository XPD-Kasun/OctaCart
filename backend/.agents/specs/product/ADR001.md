# Product Dynamic Attributes

Store Product Dynamic Attributes as Slice of Attribute in Database

# The Problem

Product attributes can be static and dynamic. Dynamic attributes by default inherited from a category. Therefore representing and storing attributes needed to be considered. Static attributes are final and Octacart reserves it. Product may add dynamic or custom attrs using `Attrs` type.

# Options Considered

- **Store attributes as **`attributes []Attr`** (document/JSON mapping for repos)**
- Separate (Entity-Attribute-Value) tables
- Fixed columns on the product table

# Rationale

Storing attributes as `attributes []Attribute` allows flexible schema evolution and simplifies loading attributes with the product entity without requiring expensive joins across tables. Fixed columns makes the app rigit and hard to evolve. We cannot say upfront these are the product props for a given product.

# Notes

Category defined attribute specifications can dictate required attributes and used for filtering, while individual products can dynamically add more attributes for special use cases.
