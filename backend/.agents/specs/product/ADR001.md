# Product Dynamic Attributes

Store Product Dynamic Attributes as Slice of Attribute in Database

# The Problem

Product attributes can be static and dynamic. Dynamic attributes by default inherited from a category. Therefore representing and storing attributes needed to be considered. Static attributes are final and Octacart reserves it. Product may add dynamic or custom attrs using `Attribute` type.

# Options Considered

- **Using a common type called Attributes with methods for various attribute types. Store as JSON**
- Store an attribute as `Attribute` and an array to hold (document/JSON mapping for repos)
- Separate (Entity-Attribute-Value) tables
- Fixed columns on the product table

# Rationale

Storing attributes as separate allows flexible schema evolution and simplifies loading attributes with the product entity without requiring expensive joins across tables. Fixed columns makes the app rigid and hard to evolve. We cannot say upfront these are the product props for a given product.

```go
type val struct {
    Type string
    Value any
}

type Attributes struct {
    attrs map[string]*val
}

func (a *Attributes) AddRange(name string, min, max int) {
    at := &val{"range", fmt.Sprintf("%d,%d", min, max)}
    a.attrs[name] = val
}

func (a *Attribute) GetRange(name string) (min, max int, err error) {
    if val, exist := a.attrs[name]; exist {
        var st, end int
        fmt.Sscanf("%d,%d", &st, &end)
        return st, end, nil
    }
    else return 0,0, errors.new("not found range")
}
```

This allows for strongly typed storage. To store this use a JSON db type and in the repo use the Add methods based on the type of the attribute. For storing (id, name, type, value) table schema can be used.

# Notes

Category defined attribute specifications can dictate required attributes and used for filtering, while individual products can dynamically add more attributes for special use cases.
