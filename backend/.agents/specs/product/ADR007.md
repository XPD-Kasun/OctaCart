# Pagination
Place Shared Pagination Primitives in the Shared Module. Since as an e-commerce system, the system requires splitting data as pages for frontends, We treat pagination as a first class citizen in this app.

# The Problem
Where to define common pagination abstractions and parameters needed by application services and driving adapters.

# Options Considered
- Redefine pagination per bounded context
- Place pagination inside driving HTTP middleware/adapters only
- **Define core pagination structures and contracts in `internal/shared`**

# Rationale
Pagination is a ubiquitous requirement across multiple bounded contexts (product, order, customer) and both driving and driven adapters, warranting a reusable contract in `internal/shared`.

# Notes
Applicable across both REST and GraphQL driving adapters.
